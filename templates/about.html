About RogueDB

RogueDB is a database of candidate Free-Floating Planets (FFPs) microlensing events selected in real time by a pipeline developed by the Roman Galactic Exoplanet Survey Project Investigation Team (RGES-PIT).

In the context of this pipeline, an "event" is considered to be an interval of brightening detected in the timeseries photometry from a source star. Detected events are passed to two independent classification packages (pyAethra and a neutral network classifier), which identify FFP candidates and attempt to flag false positives such as flares. RogueDB is designed to be the repository for the output from this software, and a flexible interface for exploring the results.

Alert Ingest and Model Fitting

When an alert is ingested into RogueDB, it immediately fits a range of different models to the segment of the lightcurve containing the event. These include:

  • Straight line models fitted to the whole lightcurve segment and just the baseline data,
  • Point-Source, Point-Lens microlensing models,
  • Finite-Source, Point-Lens microlensing models,
  • Davenport flare models,
  • Pitkin flare models.
The results of these models are used to compute a range of diagnostic parameters which are available for review on RogueDB's event detail pages.

These model fits are performed three times for each event: when a new alert is ingested; 2 days later and 1 week after the first alert. RogueDB stores the results of all of these fits, but the results displayed in the event details pages are those from the most recent fit.

Cutfiles

Cutfiles provide a mechanism for querying and selecting subsets of FFP candidates according to user-defined criteria in a way that is reproducible.

The results of all model fits and their results are versioned and timestamped within RogueDB. When you compose a cutfile query you can include a date - this ensures that you retrieve the results of models fitted up until that date. Queries can be composed with any combination of source, event and event model diagnostic parameters, and then stored as a JSON file for future reference. These files can be uploaded in order to repeat the query.
